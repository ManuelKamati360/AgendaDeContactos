Este projeceto, teve como principal objectivo, introduzir os conceitos de desenvolvimento de um sistema/webapp em Java Web ou JEE. Bem como, a implementação de uma API RESTfull em Java. Simulando um "__SPA__" com Java...

Pois, ele permitiu conhecer e aplicar diversas técnicas e tecnologias envolvidas no processo de desenvolvimento web e não só, como:  
- A criação de um sistema Java Web fullstack, desde a prototipação à implantação...
- A integração de um SGBD em webapps java...
- A criação de um backend java com rotas e serviços...
- Criação de uma API-RESTfull com Java...
- Criação de um frontend web...
- Integração/consumo de uma API-WEB RESTfull em um frontend web...
- Testes de uma API-RESTfull Web com ferramentas adoptadas no mercado profissional...
- Uso de umsistema de versionamento adoptado no mercado profissional...

## FRONTEND

#### STACK WEB BÁSICA (HTML/CSS/JS)

## BACKEND

#### JAVA 25
Foi a linguagem usada para o desenvolvimento de todo o backend do sistema. Com ela, construíram-se a API e as seguintes camadas:
- __Model__: serviu, para a modelagem das entidades do BD, usando "__Java-annotations__" para facilitar a serialização de objetos para __JSON__ ao longo do código...
- __Database__: serviu, para a modelagem da conexão ao BD, gerando conexões via "__JNDI__" (Java Naming and Directory Interface, api usada para acesso à recursos externos ao servidor, em webapps java modernos, como bancos de dados)...
- __Database Access Object__ (__DAO__): serviu, para lógica de conexão com o BD, as operações de leitura e escrita no BD...
- __Service__: serviu, para orquestrar o funcionamento do sistema, instanciando nela, as classes de modelagem e utilitário, assim como o exposição dos sistema apartir da sua integração com a API...
- __Controller/API__: serviu, para a construção da API do sistema, usando Java SERVLETs para a definição e exposição das rotas dos serviços existentes no sistema...

#### API
Foi construida, usando a linguagem Java sob o padrão __API-RESTfull__. Usando endpoints que retornam serviços em vez de acões, com os principais __verbos HTTP__ que são eles:
- "__/contatos__": usado para as operações CRUD do sistema, com os seguintes verbos http:
    - __GET__ /contatos -> para listar os contatos de forma geral/todos e de forma personalizada, usando critérios como: nome, telefone e email... 
    - __POST__ /contatos -> para a inserção/registo de novos contatos no sistema... 
    - __PUT__ /contatos -> para a actualização de contatos no sistema... 
    - __DELETE__ /contatos -> para a remoção de contatos do sistema... 
- "__/diagnostico__": usado para verificar o estado de funcionamentos dos serviços do sistema, via browser...

##### SGBD MySQL  
Foi usado para a persistencia dos dados do sistema, criando-se um banco com uma única entidade que dela são extraídas as métricas e aplicado o CRUD dos do sistema. Apartir de query's SQL, Views e Stored Procedures. Encontrados no directório ([AgendaDeContactos/docs/diagramas"](https://github.com/ManuelKamati360/AgendaDeContactos/tree/main/docs/db/script))"...


## APACHE TOMCAT SERVER
Foi usado para a implantação local durante o procecesso de desenvolvimento do sistema. Ele é o um dos mecanismos que permite o desenvolvimento Java Web, fornecendo uma abstração do JDK que interprete e chama o compilador __JIT__, __Garbage-colletor__, __JVM__ entre outros recursos do Java, sem a necessáriamente compilar o código fonte. Servindo também para a hospedagem do fronten de forma integrada ao backend, eleimendo a necessidade de uso de outros servidores como o __NGINX__...
